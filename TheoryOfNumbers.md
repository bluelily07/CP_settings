## Делимость

Число `a` делится на число `b` нацело, если существует такое целое `k`, что `a = b * k`. Записывается это как `b | a` (b делит a)

Если `a` не делится на `b` нацело, у деления остаётся остаток. Для этого случая работает **деление с остатком**:

```
a = b * q + r,  где 0 <= r < b
```

`q` - это частное, `r` - это остаток.

**Важные факты про делимость:**

- Если `a` делится на `c` и `b` делится на `c`, то и `(a + b)` делится на `c`, и `(a - b)` делится на `c`.
- Если `a` делится на `c`, то `a * k` тоже делится на `c` при любом целом `k`.
- Если `a` делится на `b`, а `b` делится на `c`, то `a` делится на `c` (транзитивность).

Может это и очевидные факты, но на них построенны 90% подобных задач, их нужно выучить и уметь увидеть в формуле, что иногда бывает не очевидно.

## Признаки делимости

Признак делимости - это способ понять, делится ли число на `k`, не выполняя само деление, а просто посмотрев на цифры числа.

- **На 2** - если последняя цифра чётная (0, 2, 4, 6, 8).
- **На 5** - если последняя цифра 0 или 5.
- **На 10** - если последняя цифра 0.
- **На 4** - если число, образованное последними двумя цифрами, делится на 4.
- **На 8** - если число, образованное последними тремя цифрами, делится на 8.
- **На 3** - если сумма всех цифр числа делится на 3. (пример: 5! = 120, 1 + 2 + 0 = 3, следовательно 5! | 3)
- **На 9** - если сумма всех цифр числа делится на 9. (6! = 720, 7 + 2 + 0 = 9, следовательно 6! | 9)
- **На 11** - если знакочередующаяся сумма цифр (справа налево: +, -, +, -...) делится на 11. (9163 = 3 - 6 + 1 - 9 = -11, следовательно, 9163 | 11)

**Почему признаки для 2, 5, 10, 4, 8 работают через последние разряды?**

Число можно расписать через разряды: `N = ... + d2*100 + d1*10 + d0`. Все слагаемые, кроме последних, содержат множитель `10`, `100` и т.д. - а значит гарантированно делятся на 2, 5, 10 (и на 4, 8, если взять два/три последних разряда). Поэтому делимость всего числа на эти делители зависит только от "хвоста" числа.

**Почему признаки для 3 и 9 работают именно через сумму цифр?**

Это следует из простого наблюдения: `10 ≡ 1 (mod 9)`, то есть при делении на 9 число 10 даёт остаток 1. Значит и любая степень десятки тоже даёт остаток 1:

```
10^k ≡ 1^k = 1 (mod 9)
```

Число `N` через цифры записывается как `N = dk*10^k + dk-1*10^(k-1) + dk-2*10^(k-2) + ... + d0`. Если каждую степень `10^i` заменить на её остаток по модулю 9 (а это 1, то есть мы сокращаем все множители для цифр числа), получаем:

```
N ≡ dk + dk-1 + ... + d0 (mod 9)
```

То есть **число сравнимо со своей суммой цифр по модулю 9**. Отсюда: `N` делится на 9 тогда и только тогда, когда сумма его цифр делится на 9. То же самое рассуждение с `10 ≡ 1 (mod 3)` даёт признак для 3.

Именно поэтому среди всех признаков делимости только у 3 и 9 есть версия "через сумму цифр" - остальным делителям это свойство `10 ≡ 1` не подходит.

## Сравнения по модулю (модулярная арифметика)

Говорят, что `a` сравнимо с `b` по модулю `m`, если `a` и `b` дают одинаковый остаток при делении на `m`. Записывается так:

```
a ≡ b (mod m)
```

Равносильное определение: `a ≡ b (mod m)`, если `(a - b)` делится на `m`.

**Свойства сравнений (с ними работать так же удобно, как с обычным равенством):**

- Если `a ≡ b (mod m)` и `c ≡ d (mod m)`, то `a + c ≡ b + d (mod m)`.
- Аналогично для вычитания: `a - c ≡ b - d (mod m)`.
- Аналогично для умножения: `a * c ≡ b * d (mod m)`.
- **А вот для деления так просто нельзя** - сокращать обе части сравнения на общий множитель можно только если этот множитель взаимно прост с `m` (иначе можно потерять или получить лишние решения). Подробнее об этом - в разделе про обратный элемент.

На практике это означает, что при работе с большими числами по модулю (например, `mod = 1e9+7`) можно брать остаток на каждом шаге вычислений (после каждого `+`, `-`, `*`), а не только в конце - результат не изменится.

```
ll add(ll a, ll b, ll mod) {
    return ((a % mod) + (b % mod)) % mod;//берем остаток от каждого слагаемого, чтобы не словить overflow
}

ll mul(ll a, ll b, ll mod) {
    return ((a % mod) * (b % mod)) % mod;//то же самое для умножения
}
```

Отдельно стоит запомнить, что в C++ остаток от отрицательного числа может быть отрицательным (`-7 % 3 == -1`, а не `2`). Поэтому при вычитании по модулю всегда прибавляем `mod` перед взятием остатка:

```
ll sub(ll a, ll b, ll mod) {
    return ((a - b) % mod + mod) % mod;//прибавляем mod на случай если a - b < 0
}
```

## НОД и НОК

**НОД** (наибольший общий делитель) двух чисел `a` и `b` - самое большое число, на которое делятся и `a`, и `b` одновременно.

**НОК** (наименьшее общее кратное) - самое маленькое число, которое делится и на `a`, и на `b`.

Между ними есть простая связь:

```
НОД(a, b) * НОК(a, b) = a * b
```

То есть, зная НОД, можно сразу получить НОК:

```
НОК(a, b) = a / НОД(a, b) * b
```

(делим сначала, а не умножаем `a * b` сразу, чтобы не словить overflow раньше времени)

## Алгоритм Евклида

Алгоритм Евклида - быстрый способ находить НОД двух чисел, без перебора всех делителей.

**Идея:** `НОД(a, b) = НОД(b, a % b)`, и так продолжаем, пока один из аргументов не станет равен 0 - тогда второй аргумент и есть ответ.

**Почему это работает:** пусть `a = b*q + r`. Любой общий делитель `a` и `b` обязан делить и `r = a - b*q` (по свойству делимости из первого раздела). И наоборот, любой общий делитель `b` и `r` обязан делить `a = b*q + r`. Значит множество общих делителей у пар `(a, b)` и `(b, r)` одно и то же, а значит и НОД у них совпадает.

```
ll gcd(ll a, ll b) {
    if (b == 0) return a;//база: если b == 0, то a и есть НОД
    return gcd(b, a % b);//сводим задачу к паре поменьше
}
```

Работает за `O(log(min(a, b)))` - на каждом шаге числа уменьшаются как минимум в 2 раза за две итерации (это доказывается через свойства чисел Фибоначчи, самый медленный случай для алгоритма Евклида).

## Расширенный алгоритм Евклида

Расширенный алгоритм Евклида не просто находит `НОД(a, b)`, а ещё и находит такие целые `x` и `y`, что:

```
a*x + b*y = НОД(a, b)
```

Это называется **тождеством Безу**, и такие `x`, `y` всегда существуют для любых `a`, `b`.

```
ll extgcd(ll a, ll b, ll &x, ll &y) {
    if (b == 0) {
        x = 1;
        y = 0;
        return a;//база: a*1 + b*0 = a
    }
    ll x1, y1;
    ll d = extgcd(b, a % b, x1, y1);//рекурсивно решаем для пары (b, a % b)
    x = y1;//восстанавливаем x и y текущего шага из решения предыдущего
    y = x1 - (a / b) * y1;
    return d;
}
```

Зачем это нужно: если `НОД(a, m) = 1`, то из тождества Безу `a*x + m*y = 1`, а значит `a*x ≡ 1 (mod m)` - то есть `x` это **обратный элемент** к `a` по модулю `m` (см. следующий раздел).

## Простые числа

Простое число - число больше 1, у которого ровно два делителя: 1 и само число. Число 1 простым не считается (у него только один делитель).

**Основная теорема арифметики:** любое целое число больше 1 раскладывается на произведение простых чисел, и это разложение единственно с точностью до порядка множителей.

```
n = p1^a1 * p2^a2 * ... * pk^ak
```

**Разложение числа на простые множители (факторизация):**

```
vector<pair<ll,int>> factorize(ll n) {
    vector<pair<ll,int>> res;
    for (ll d = 2; d * d <= n; d++) {//перебираем делители только до корня из n
        if (n % d == 0) {
            int cnt = 0;
            while (n % d == 0) {//вычитаем все вхождения делителя d
                n /= d;
                cnt++;
            }
            res.push_back({d, cnt});
        }
    }
    if (n > 1) res.push_back({n, 1});//если после цикла осталось n > 1, значит это последний простой множитель
    return res;
}
```

Перебор до `sqrt(n)` достаточен, потому что если у `n` есть делитель больше `sqrt(n)`, у него обязательно найдётся парный делитель меньше `sqrt(n)` - иначе их произведение превысило бы `n`.

## Решето Эратосфена

Если простые числа нужны не по одному, а массово (например, все простые до `10^7`), перебирать делители для каждого числа отдельно слишком медленно. Решето Эратосфена находит все простые числа до `n` за `O(n log log n)`.

**Идея:** берём первое непомеченное число (оно гарантированно простое, т.к. все его делители уже были бы вычеркнуты раньше), и вычёркиваем все его кратные.

```
vector<bool> sieve(int n) {
    vector<bool> is_prime(n + 1, true);
    is_prime[0] = is_prime[1] = false;//0 и 1 не простые

    for (int i = 2; (ll)i * i <= n; i++) {
        if (is_prime[i]) {//если i ещё не вычеркнуто, значит оно простое
            for (int j = i * i; j <= n; j += i) {//вычёркиваем все кратные i, начиная с i*i (меньшие кратные уже вычеркнуты меньшими простыми)
                is_prime[j] = false;
            }
        }
    }
    return is_prime;
}
```

Начинаем внутренний цикл с `i*i`, а не с `2*i`, потому что все составные числа вида `k*i` при `k < i` уже были вычеркнуты раньше, когда мы обрабатывали множитель `k`.

## Формула Лежандра

Формула Лежандра отвечает на вопрос: **сколько раз простое число `p` входит в разложение `n!`**, не вычисляя сам факториал (который может быть гигантским числом).

```
vp(n!) = floor(n/p) + floor(n/p^2) + floor(n/p^3) + ...
```

**Почему это работает:** `floor(n/p)` считает, сколько чисел от 1 до `n` делятся на `p` хотя бы один раз (каждое такое число даёт хотя бы одну степень `p` в произведение `n!`). Но числа, делящиеся на `p^2`, дают уже вторую степень `p`, и их нужно посчитать ещё раз - это делает `floor(n/p^2)`. Аналогично для `p^3` и так далее. Суммируя, мы для каждого числа учитываем ровно столько степеней `p`, сколько у него есть на самом деле.

```
ll legendre(ll n, ll p) {
    ll count = 0;
    while (n > 0) {
        n /= p;//на каждом шаге n делим на p - это и есть floor(n/p^k) накопительно
        count += n;
    }
    return count;
}
```

Именно через эту формулу можно строго доказать факт, который мы использовали в задаче про Перестукина: при `n >= 6`, `legendre(n, 3) >= 2`, значит `9 = 3^2` точно делит `n!`.

## Быстрое возведение в степень

Наивное возведение `a^n` за `n` умножений слишком медленное для больших `n` (например, `n ~ 10^9`). Бинарное возведение в степень делает то же самое за `O(log n)`.

**Идея:** `a^n` можно разбить через чётность степени:

```
a^n = (a^(n/2))^2         если n чётное
a^n = a * (a^(n/2))^2     если n нечётное (n/2 - целочисленное деление)
```

Так степень каждый раз уменьшается вдвое, вместо того чтобы уменьшаться на 1.

```
ll binpow(ll a, ll n, ll mod) {
    ll res = 1;
    a %= mod;
    while (n > 0) {
        if (n & 1) res = res * a % mod;//если текущий бит степени 1, домножаем результат на a
        a = a * a % mod;//возводим a в квадрат для следующего бита
        n >>= 1;//переходим к следующему биту степени
    }
    return res;
}
```

## Малая теорема Ферма и обратный элемент по модулю

**Малая теорема Ферма:** если `p` - простое число, и `a` не делится на `p`, то:

```
a^(p-1) ≡ 1 (mod p)
```

Из этого сразу следует, как искать **обратный элемент** `a^(-1)` по модулю `p` (то есть такое число `x`, что `a * x ≡ 1 (mod p)`, аналог деления на `a`):

```
a * a^(p-2) ≡ a^(p-1) ≡ 1 (mod p)
```

Значит `a^(-1) ≡ a^(p-2) (mod p)`, и его можно посчитать через бинарное возведение в степень за `O(log p)`:

```
ll inv(ll a, ll p) {
    return binpow(a, p - 2, p);//работает только если p простое
}
```

Это и есть причина, почему "деление" по модулю нельзя делать напрямую оператором `/` - вместо этого умножают на обратный элемент. Если `p` не простое, но `НОД(a, p) = 1`, обратный элемент всё равно существует, но искать его нужно уже через расширенный алгоритм Евклида (тождество Безу), а не через теорему Ферма.

## Разбор задачи: стёртая цифра в записи n!

Возвращаемся к задаче про Перестукина, чтобы закрепить сразу несколько идей из этого конспекта вместе.

**Условие (кратко):** дана строка - запись числа `n!` (1 ≤ n ≤ 10000), в которой одна ненулевая цифра заменена на `#`. Нужно восстановить эту цифру.

**Решение:**

Вычислять `n!` напрямую нельзя - число может занимать до 35660 цифр. Значит нужно свойство, которое проверяется по цифрам числа, а не по самому числу.

Единственные признаки делимости, которые выражаются через **сумму цифр** - это признаки на 3 и 9 (доказано в разделе "Признаки делимости"). Раз пропала ровно одна цифра, а остальные цифры мы знаем, сумму цифр легко восстановить с точностью до одного неизвестного слагаемого - значит это подходящий инструмент.

Проверяем через формулу Лежандра, делится ли `n!` на 9 при достаточно больших `n`:

```
vp(n!, 3) = floor(n/3) + floor(n/9) + ...
```

При `n >= 6` это выражение уже `>= 2`, значит `3^2 = 9` точно делит `n!`. Для `n < 6` (то есть `n! = 1, 2, 6, 24, 120`) это свойство не гарантировано - эти случаи разбираются отдельно, вручную, так как таких `n` всего пять и записи короткие.

Раз `n!` делится на 9 при `n >= 6`, по доказанному в разделе про признаки делимости - сумма цифр `n!` тоже делится на 9. Считаем сумму известных цифр `S`, тогда пропавшая цифра `d` обязана удовлетворять:

```
(S + d) % 9 == 0
d = (9 - S % 9) % 9
```

Так как по условию `d != 0`, а 0 и 9 дают одинаковый остаток по модулю 9 - если формула выдаёт `d = 0`, на самом деле ответ `d = 9`.

```
void solve() {
    string s;
    cin >> s;

    if (s.size() <= 3) {
        //n < 6 разбираем отдельно, значения 1!, 2!, 6, 24, 120 короткие и известны заранее
        //здесь достаточно сопоставить длину и известные цифры с этим небольшим списком
    } else {
        ll sum = 0;
        for (char c : s) {
            if (c != '#') sum += c - '0';//суммируем только известные цифры
        }
        ll d = (9 - sum % 9) % 9;
        if (d == 0) d = 9;//цифра не может быть нулём по условию
        cout << d << "\n";
    }
}
```

**Итоговый паттерн, который стоит запомнить:** если в задаче огромное число, от которого известны почти все цифры кроме одной (или нужно что-то доказать про его цифры не вычисляя само число) - в первую очередь проверяй признак делимости на 9 (или 3), и ищи, что даёт гарантию такой делимости через формулу Лежандра или разложение на множители.
